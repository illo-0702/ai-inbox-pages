# 3분 시연 스크립트 (기획서 16장 기준)

## 사전 준비

1. `npm run build && npm start` (또는 배포 URL) — 개발 모드의 Next.js 배지가 보이지 않게 프로덕션으로 연다.
2. 푸터 [데모 데이터 삭제]로 빈 대시보드에서 시작한다.
3. AI 제공자를 쓰려면 `.env.local`에 키를 넣는다. 키가 없거나 호출이 실패하면 화면에 "데모 분석(규칙 기반)" 배지가 뜨고 규칙 엔진으로 같은 흐름이 진행된다. 실시간 처리와 녹화본은 구분해서 안내한다.
4. 입력 화면 상단의 예시 버튼 ①②③이 받은 날짜까지 고정해서 채워준다(9/18 09:00, 9/19 10:00, 9/19 15:00).

## 진행

| 시간 | 화면·동작 | 말할 내용 |
|---|---|---|
| 0:00–0:20 | 빈 대시보드 | "같은 업체에서도 여러 담당자가 조건을 바꿔 전달합니다. 메시지를 다시 읽지 않고 지금 할 일만 보고 싶습니다." |
| 0:20–0:55 | [정보 추가] → ① 김과장 첫 요청 → [AI로 정리하기] → 결과(A창호·김과장·3,000,000원·2026.09.20·새 업무) → [저장] | "받은 요청을 넣으면 해야 할 일이 만들어집니다. '20일'은 받은 날짜 기준으로 2026년 9월 20일로 해석합니다." |
| 0:55–1:35 | ② 이대리 마감 변경 → 분석 → "기존 관계 A창호 / 기존 업무 3,000,000원 송금" + 비교표 **마감 09.20 → 09.22** → [변경 반영] | "담당자가 달라도 같은 업무를 찾아 마감만 바꿉니다. 금액이 없다고 기존 금액을 지우지 않습니다." |
| 1:35–2:10 | ③ 잠정 변경 → 분석 → **변경 가능성** 배지, "2026.09.24로 변경될 가능성이 있습니다. 현재 마감은 2026.09.22입니다." → [나중에 확인] | "애매한 말은 확정하지 않습니다. 현재 마감은 9/22 그대로이고, 확인할 항목으로 남습니다." |
| 2:10–2:35 | 대시보드: 확인 필요 1건 + 카드(2026.09.22까지, 최근 변경 09.20 → 09.22) → 관계 이름 클릭 → 타임라인 | "과거 변경과 지금 유효한 조건을 함께 봅니다. 원문이 아니라 누가 무엇을 바꿨는지만 남깁니다." |
| 2:35–3:00 | 확인 필요 항목 → [기존 유지] → 대시보드 [완료] → 완료 탭 | "사용자는 지금 해야 할 일을 확인하고 처리하면 됩니다. 잘못 누르면 되돌릴 수 있습니다." |

## 마지막 확인 (기획서 16장)

1. 담당자 두 명(김과장·이대리)이 같은 관계 A창호에 묶인다.
2. 송금 업무는 한 건으로 유지된다.
3. 금액 3,000,000원은 유지되고 마감만 09.20 → 09.22로 바뀐다.
4. 잠정 변경(9/24)은 현재 마감을 덮어쓰지 않는다.
5. 완료 상태를 직접 바꿀 수 있다(되돌리기 가능).

## 심사위원 직접 테스트 안내

1. 첫 요청 입력 — 예: "B상사 박팀장입니다. 25일까지 150만원 송금 부탁드립니다."
2. 다른 담당자의 날짜 변경 입력 — 예: "B상사 최대리입니다. 송금은 28일까지 부탁드립니다."
3. 최종 날짜(28일)와 업무 수(1건)를 확인한다.

업체명이 없는 메시지("이영호 대리입니다. 송금은 25일까지 부탁드립니다.")를 넣으면 자동으로 합치지 않고 "이 담당자는 어느 관계에 속하나요?"를 묻는다.
