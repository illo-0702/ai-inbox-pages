## 해결하고자 한 문제 (한 줄)

여러 담당자가 여러 곳으로 조건을 바꿔 보내서, 무엇이 최종 조건이고 지금 무엇을 해야 하는지 매번 메시지를 다시 뒤져야 하는 문제

## AI 활용 방식 및 결과 (500자 이내)

받은 메시지를 붙여넣거나 PDF·이미지로 올리면 AI(LLM)가 발신자·업체·요청 종류·금액·마감·잠정 표현을 구조화합니다. AI 결과는 '제안'으로만 쓰고, 관계·업무 연결과 변경 반영은 서버의 결정적 규칙이 맡아 날짜('22일', '내일')와 금액('300만원 말고 350만원')을 다시 검증합니다. 그 결과 김과장의 '20일까지 300만원 송금'과 이대리의 '송금은 22일까지'가 하나의 업무로 이어져 마감만 09.20→09.22로 바뀌고, '될 것 같긴 한데 확인해볼게요' 같은 잠정 표현은 현재 마감을 덮어쓰지 않고 확인 항목으로 남습니다. 원문은 저장하지 않고 구조화된 변경 이력만 남깁니다. 개발은 Claude Code로 설계·구현·검수했고 자동 테스트 185개와 기획서 수용 테스트 20개를 통과했습니다.

## 사용 AI툴 및 기술 스택 (선택할 칩)

- **Next.js**, **React** — 웹 앱
- **Claude** — Claude Code로 설계·구현·검수
- **OpenRouter** — 배포 사이트의 분석 호출 경로 (Vercel에 OpenRouter 키를 넣은 경우)
- **Gemini** — OpenRouter로 호출하는 분석 모델(`google/gemini-3.5-flash-lite`) 또는 Gemini 직접 연결
- **Vercel** — 배포

목록에 없는 것: TypeScript, Tailwind CSS, Turso(libSQL), Zod, Vitest, OmniRoute(로컬 개발용 AI 라우터).

## 스크린샷 (최대 5장, 16:9)

1. 대시보드 — 확인 필요 1건 + 현재 할 일 카드(2026.09.22까지, 최근 변경 09.20 → 09.22)
2. 분석 결과 — 이대리 메시지: 기존 관계 A창호 / 기존 업무 / 마감 09.20 → 09.22 비교
3. 잠정 변경 — "변경 가능성" 배지, "현재 마감은 2026.09.22입니다"
4. 관계 상세 타임라인 — 김과장·이대리, 등록 → 변경 적용 → 보류 → 기존 유지
5. 모바일 화면 — 같은 카드가 잘림 없이 보이는 휴대폰 화면
